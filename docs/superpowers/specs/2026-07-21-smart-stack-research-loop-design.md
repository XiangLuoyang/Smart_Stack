# Smart Stack 个人股票研究闭环设计

**日期：** 2026-07-21
**状态：** 已确认设计
**产品定位：** 面向本地单用户的中国 A 股预测研究、模拟操作与持续复盘系统

## 1. 背景

Smart Stack 最初的目标是将机器学习量化预测、技术指标、风险分析和 LLM 解读结合起来，支持单股分析以及沪深成分股批量筛选。当前 React + FastAPI 工作台增加了账户、订单、持仓、风控和回测，但产品中心逐渐偏向模拟交易。

本设计重新确立主线：预测和分析是核心；模拟操作是研究判断的验证工具；记录和复盘负责将一次性分析沉淀为可持续学习的个人研究体系。

核心闭环为：

```text
沪深300筛选 -> 单股10日预测分析 -> 建立研究案例 -> 人工模拟操作
             -> 持续追加证据与判断 -> 10日到期复盘 -> 反馈模型和个人决策
```

## 2. 已确认约束

- 仅覆盖中国 A 股现货，包括沪深主板、创业板和科创板。
- 仅用于可靠模拟交易，不连接真实券商。
- 仅在本地单机使用，不建设云同步、多租户或公开服务。
- 使用单一模拟账户；保留底层 `account_id` 兼容字段，但 UI 不提供多账户管理。
- 交易时段行情刷新目标为 15 秒。
- 所有模拟订单必须由用户人工确认；模型、选股和 LLM 不得自动下单。
- 核心预测期限固定为 10 个交易日。
- 预测、研究判断、证据、决策和复盘采用追加式记录；历史记录不得被最新结果覆盖。

## 3. 目标与非目标

### 3.1 目标

1. 每日对沪深300进行可解释的10日预测筛选。
2. 为单只股票提供量化、技术、风险和 LLM 分栏展示的深度分析。
3. 将一次分析冻结为不可改写的研究快照，并持续追加证据和判断变化。
4. 将模拟操作与研究案例关联，区分模型判断、人工判断和执行结果。
5. 在第10个交易日自动结算预测，形成标准化复盘。
6. 长期衡量模型版本、Top10筛选、人工判断和执行纪律的真实表现。
7. 在本地环境中提供可靠启动、备份、恢复、健康检查和故障提示。

### 3.2 非目标

- 真实券商接入和自动交易。
- 港股、美股、期货、期权、融资融券和做空。
- 多用户、权限、云端协作和商业化部署。
- tick 级撮合或交易所级实时行情。
- 以 LLM 文本替代可验证的量化预测。
- 在第一阶段追求复杂深度学习模型或大量策略插件。

## 4. 设计原则

### 4.1 研究优先

首页、导航和数据模型均围绕“发现、研究、决策、学习”组织。账户资产和订单是下游验证数据，不作为产品主轴。

### 4.2 历史不可改写

正式预测、筛选排名、研究快照和复盘结果一旦写入不得原地修改。观点变化通过新的证据记录和决策记录表达。

### 4.3 预测必须可验证

每份预测都必须具备统一期限、输入数据截止时间、模型版本、输出区间和到期结果。无法说明数据或模型版本的结果不属于正式预测。

### 4.4 模型与解释分离

量化模型负责数值预测；技术指标提供可解释信号；LLM 负责总结、风险提示和反方观点。LLM 不直接进入数值预测评分。

### 4.5 失败显式化

数据过期、数据源切换、模型降级、扫描部分失败和 LLM 缺失都必须展示。系统不得用零值、旧值或模糊成功状态掩盖故障。

## 5. 总体架构

保留现有 React、FastAPI、SQLAlchemy、SQLite、APScheduler 和 Docker 技术栈，将业务划分为五个边界明确的模块。

```text
数据中心
  -> 预测与筛选中心
      -> 单股研究中心
          -> 决策与模拟操作中心
              -> 复盘与学习中心
```

### 5.1 数据中心

负责行情、日线、复权、交易日历、沪深300成分、数据源状态、缓存和数据批次。盘中15秒行情服务观察与模拟操作；收盘后日线数据服务正式预测和复盘。

### 5.2 预测与筛选中心

负责模型注册、特征生成、10日预测、每日沪深300完整排名、Top10候选和模型到期评价。每次任务生成唯一运行记录并允许部分成功。

### 5.3 单股研究中心

聚合预测、技术指标、风险指标、LLM 报告、历史预测表现和既往研究案例。用户可以把当前分析冻结为研究案例。

### 5.4 决策与模拟操作中心

记录方向、理由、预期区间、支持证据、反方观点、失效条件、计划价格和信心程度。模拟订单从研究案例发起并要求人工确认。

### 5.5 复盘与学习中心

在预测到期后写入标准结果，分离评价模型预测、人工判断和实际执行，并按模型、行业、市场状态和错误标签汇总长期表现。

## 6. 核心数据对象

| 对象 | 职责 | 可变性 |
| --- | --- | --- |
| `MarketDataBatch` | 记录数据批次、来源、截止时间和校验结果 | 写入后不可修改 |
| `UniverseSnapshot` | 保存当日沪深300成分股 | 写入后不可修改 |
| `ModelVersion` | 保存模型、参数、特征和训练截止时间 | 新版本替代，不覆盖 |
| `ScreeningRun` | 保存一次完整扫描及其状态 | 任务结束后冻结 |
| `ScreeningCandidate` | 保存每只股票的排名、预测和失败原因 | 随运行冻结 |
| `PredictionSnapshot` | 保存单股正式10日预测 | 不可修改 |
| `ResearchCase` | 保存首次研究判断和预测关联 | 首次冻结；状态可结束 |
| `EvidenceEntry` | 保存支持、反对或中性证据 | 仅追加 |
| `DecisionEntry` | 保存用户判断及其变化 | 仅追加 |
| `SimulatedOrder` / `SimulatedTrade` | 保存人工确认的模拟委托和成交 | 状态机更新，成交历史不可改写 |
| `ReviewResult` | 保存到期市场结果和用户复盘 | 自动结果冻结；用户复盘追加 |
| `PerformanceMetric` | 保存按固定口径计算的聚合统计 | 按批次重算并版本化 |

所有正式记录必须包含创建时间、业务日期、来源或生成者，并通过稳定 ID 建立关联。

## 7. 产品页面

### 7.1 今日工作台

展示当日扫描状态、Top10候选、活跃研究案例、即将到期预测、待复盘项目、今日模拟操作、数据源状态和模型状态。

### 7.2 沪深300选股

展示完整排名和 Top10，包括10日预期收益、方向概率、置信区间、相对沪深300预期超额收益、风险指标、排名变化、历史入选次数、模型版本和数据截止时间。所有每日结果可回看。

### 7.3 单股研究

分栏展示 K 线与量价、10日预测、技术指标、风险指标、LLM 报告、历史预测成绩、当前证据和既往案例。预测、技术信号和 LLM 不合并成含义不清的总分。

### 7.4 研究案例

建立案例时冻结当前分析，并要求填写方向、核心理由、预期收益区间、支持证据、最大反方观点、失效条件、计划买入价、目标价、止损价和信心程度。后续变化通过追加记录表达。

### 7.5 模拟操作

从研究案例发起人工确认订单。支持市价、限价、撤单、T+1、100股整手、费用、涨跌停、停牌、资金冻结和持仓冻结。界面仅展示单一模拟账户。

### 7.6 复盘中心

展示待复盘和已完成项目。到期结果包括实际10日收益、方向、预测误差、区间覆盖、相对沪深300超额收益、最大有利波动和最大不利波动。用户补充归因和错误标签。

### 7.7 模型表现

展示各模型版本的方向准确率、收益误差、区间覆盖率、排名秩相关、Top10收益、Top10超额收益，以及按行业和市场状态划分的稳定性。另行展示人工判断增量和执行偏差。

### 7.8 设置与健康状态

配置数据源、行情刷新、LLM、费用和备份；显示数据新鲜度、任务队列、最后成功扫描、模型版本、存储空间和备份状态。

## 8. 预测契约

### 8.1 正式目标

以预测基准日复权收盘价为起点，预测第10个交易日复权收盘价对应的收益率，并同时输出：

- 上涨、下跌和震荡概率；
- 10日收益中位数；
- 预测下界和上界；
- 相对沪深300的预期超额收益；
- 10日最大有利和最大不利波动估计；
- 数据质量和预测可用状态。

正式预测每天收盘后生成一次。盘中15秒行情不得反复改写当日正式预测。

### 8.2 模型体系

- 基线模型：历史均值、动量、均线和简单统计模型。
- 主力模型：经过时间序列样本外验证的机器学习模型。
- 挑战模型：LSTM 或其他深度学习模型。
- 组合模型：仅在多个样本外窗口持续优于基线后启用。

每份预测必须保存模型名称、版本、参数摘要、特征版本、训练数据截止日期、输入数据批次、生成时间和降级状态。

### 8.3 防止数据泄漏

- 按时间划分训练、验证和测试数据，禁止随机打乱。
- 使用滚动或扩展窗口进行 walk-forward 验证。
- 特征只能使用预测时已经存在且可获得的数据。
- 历史评价使用当时保存的成分股快照，避免幸存者偏差。
- 调参不能反复消费同一最终测试集。
- 模型升级创建新版本，不重新计算或覆盖旧预测。

### 8.4 到期评价

第10个交易日收盘后计算：

- 方向准确率；
- 10日收益预测误差；
- 预测区间覆盖率；
- 候选排名与实际收益的秩相关；
- Top10平均收益和相对沪深300超额收益；
- 最大有利和最大不利波动；
- 按行业、波动环境和市场状态划分的稳定性。

人工评价单独记录方向判断、失效条件、计划遵守、是否操作、执行偏差和错误标签，避免将模型错误与执行错误混为一谈。

## 9. 每日数据流

1. 盘中每15秒刷新自选股、持仓股和当前研究标的行情。
2. 收盘后拉取并校验沪深300成分、日线和复权数据。
3. 创建唯一数据批次并冻结当日正式模型输入。
4. 运行沪深300筛选，保存完整排名、成功数和失败数。
5. 为合格标的生成10日预测快照。
6. 用户从候选进入单股研究并按需建立研究案例。
7. 交易日历每天识别已到达第10个交易日的预测。
8. 到期后写入市场实际结果并进入人工复盘队列。
9. 人工复盘完成后刷新模型、筛选和个人执行统计。

任务必须幂等：同一业务日期、股票、模型版本和预测期限只能存在一份正式预测。重复调用返回已有结果或恢复未完成任务。

## 10. 故障处理

- 主数据源失败时切换备用源，并记录来源、切换原因和时间。
- 数据缺失、时间戳过期、复权异常或价格异常时不生成正式预测。
- 沪深300扫描允许部分成功，并逐只记录失败原因。
- LLM 失败不阻塞量化预测或研究案例，只将报告标记为缺失。
- 主力模型失败时只允许使用已验证的基线模型，并标记为降级预测。
- 盘中行情过期时展示最后更新时间并禁止无提示模拟成交。
- 后台任务、API 请求和行情缓存不得共享可变 SQLAlchemy Session。
- 所有关键任务具有运行 ID、状态、开始/结束时间、错误摘要和重试信息。
- SQLite 数据库和研究附件每日自动备份，支持一键导出、校验和恢复。

## 11. 测试策略

### 11.1 计算测试

覆盖收益率、交易日、复权、技术指标、费用、T+1、整手、涨跌停、资金冻结、持仓冻结和复盘指标。

### 11.2 数据测试

覆盖缺失值、重复行、异常价格、时间戳、复权连续性、成分股快照和多数据源一致性。

### 11.3 模型测试

覆盖未来数据泄漏、时间切分、特征版本、结果可复现、模型序列化和基线比较。

### 11.4 流程测试

覆盖“筛选 -> 预测 -> 研究案例 -> 模拟操作 -> 10日结算 -> 人工复盘 -> 统计更新”的完整链路。

### 11.5 并发与恢复测试

覆盖重复任务、任务中断、SQLite写入竞争、数据源故障、行情陈旧、备份恢复和进程重启。

### 11.6 前端验收

覆盖数据时间戳、故障状态、模型版本、历史快照、证据追加、人工确认订单、待复盘队列和模型表现页面。

## 12. 模型上线门槛

新模型上线为主力模型之前必须：

1. 在未参与调参的样本外时间窗口优于简单基线。
2. 在多个市场阶段保持方向、误差和排序表现的稳定性。
3. Top10相对沪深300的改善具有可解释性，而非来自单一行业集中。
4. 明确记录训练数据、代码版本、参数、特征和评估结果。
5. 能在固定数据批次上复现实验结果。

如果新模型只在单个指标或单个区间占优，则保持挑战模型状态，不替换主力模型。

## 13. 分阶段交付

### 阶段一：可信预测底座

修复数据适配、时间序列评价、模型注册、10日预测快照、成分股快照和到期结算。验收结果是系统能够可靠回答“当时预测了什么，使用什么数据和模型，后来结果如何”。

### 阶段二：研究闭环

完成沪深300历史筛选、单股研究、研究案例、证据追加、判断变化、待复盘队列和人工复盘。阶段一与阶段二完成后，产品具备核心使用价值。

### 阶段三：操作嵌入

将单账户模拟订单与研究案例关联，修复资金/持仓冻结和并发一致性，落实 A 股交易规则，并生成执行偏差归因。

### 阶段四：学习与优化

完成模型表现、Top10表现、人工判断增量、错误标签、行业表现和市场状态分析。

### 阶段五：本地产品化

完成一键启动、配置检查、依赖锁定、健康状态、日志、备份恢复、用户文档和稳定性验收。

每个阶段应形成独立、可运行、可测试的版本；不得以阶段五的打包工作阻塞前两阶段的研究价值交付。

## 14. 完成定义

系统满足以下条件时，才可称为“完整可用的个人研究操作台”：

- 可以稳定生成并保存每日沪深300完整筛选结果。
- 可以对任意合格 A 股建立标准10日预测和单股研究案例。
- 可以查看当时数据、模型、预测、LLM报告和人工判断的原始快照。
- 可以持续追加证据和判断变化，且不能改写历史。
- 可以将人工模拟操作与研究案例关联并保证账本一致。
- 可以自动识别10日到期预测并完成标准市场评价。
- 可以区分模型、人工判断和执行表现。
- 可以按模型版本和时间区间查看长期成绩。
- 数据失败和降级状态对用户清晰可见。
- 本地数据可以备份、校验和恢复。
- 核心测试、完整链路测试和恢复测试全部通过。

## 15. 实施计划拆分原则

本设计覆盖多个相互依赖的子系统，后续不使用一份巨型实施计划。实施计划应按五个交付阶段分别编写；每个计划必须明确数据库迁移、后端接口、前端页面、测试、数据迁移与验收命令，并以前一阶段的稳定接口作为输入。
